# Analysis & Integration Strategy: No Fluff Jobs Scraper

This document outlines the detailed strategy and code modifications required to integrate the No Fluff Jobs scraper (`src/scrapers/nofluffjobs.ts`) alongside the existing Profession.hu scraper into the `scraperManager.ts` and the SQLite database.

---

## 1. Import and Integration of Scraper Functions

### Naming Collisions & Aliasing
Both `src/scrapers/profession.ts` and `src/scrapers/nofluffjobs.ts` export:
- `scrapeJobDetails(link: string): Promise<string>`
- `ScrapedJob` interface (representing the common data structure for a scraped job)

To avoid naming collisions and maintain clear separation, the functions should be imported into `src/scrapers/scraperManager.ts` using aliases:

```typescript
import { scrapeProfessionHu, scrapeJobDetails as scrapeProfessionDetails } from './profession';
import { scrapeNoFluffJobs, scrapeJobDetails as scrapeNoFluffDetails } from './nofluffjobs';
```

---

## 2. Location Mapping Strategy

### Configured Locations
The user selects locations via the frontend (e.g. `budapest`, `pecs`, `debrecen`, `szeged`, `gyor`, `tavmunka`, `home_office`), which are stored as an array of lowercase strings in the SQLite database under the `config` table with `key = 'locations'`.

### Individual Scraper Mapping
Both scrapers are already designed to accept this array of lowercase keys and map them internally:
- **Profession.hu (`profession.ts`)** maps keys using `LOCATION_MAP` to an object containing a `slug`, numeric `id`, and optional `homeOfficeId`.
- **No Fluff Jobs (`nofluffjobs.ts`)** maps keys using `LOCATION_MAP` and `FALLBACK_CITY_MAP` to city names like `Budapest` or `remote`.

### Mapping Flow
1. `scraperManager.ts` reads the configuration array from the database.
2. It passes this array of raw keys (e.g., `['budapest', 'tavmunka']`) directly to both scraper functions.
3. If a selected key is missing from the mapping dictionary of a scraper (for example, if `pest` or `miskolc` is selected but not defined in No Fluff Jobs' `LOCATION_MAP`), it is safely filtered out and ignored for that platform without causing errors.

## 3. Merging, Detail Fetching, Duplicate Prevention, and DB Operations

### Merging Results
To run both scrapers efficiently and maximize throughput, they should be executed concurrently using `Promise.all`. 

To ensure fault tolerance, each promise should catch its own errors individually. This prevents an error in one scraper from failing the entire scraping process.
```typescript
const [professionJobs, noFluffJobs] = await Promise.all([
  scrapeProfessionHu(keyword, locations).catch(err => {
    console.error(`Profession.hu search failed for "${keyword}":`, err.message);
    report.errors.push(`Profession.hu search failed: ${err.message}`);
    return [];
  }),
  scrapeNoFluffJobs(keyword, locations).catch(err => {
    console.error(`No Fluff Jobs search failed for "${keyword}":`, err.message);
    report.errors.push(`No Fluff Jobs search failed: ${err.message}`);
    return [];
  })
]);

const jobs = [...professionJobs, ...noFluffJobs];
```

### In-Memory Deduplication
Before querying the database, we can deduplicate the combined jobs array in memory using a `Map` keyed by `job_id`:
```typescript
const uniqueJobsMap = new Map<string, typeof jobs[0]>();
for (const job of jobs) {
  uniqueJobsMap.set(job.job_id, job);
}
const uniqueJobs = Array.from(uniqueJobsMap.values());
```

### Detail Fetching Routing
During the job processing loop, the manager must invoke the correct detail scraping function based on the `job.platform` attribute:
```typescript
let detailText = '';
if (job.platform === 'profession') {
  detailText = await scrapeProfessionDetails(job.link);
} else if (job.platform === 'nofluffjobs') {
  detailText = await scrapeNoFluffDetails(job.link);
} else {
  console.warn(`Unknown platform: ${job.platform}`);
  continue;
}
```

### Database Persistence
No modifications are required in `src/db/database.ts` because:
- The `jobs` table has a `platform` column that is a standard `TEXT` data type.
- The `job_id` is defined as `TEXT UNIQUE NOT NULL`, preventing duplicates.
- The `job_id` values generated by the scrapers already contain platform prefixes (`profession-<id>` and `nofluffjobs-<slug>`), ensuring they are globally unique.
